# ADR 0009: 代码风格与文档约定

## 状态

已接受（2026-07-30 → 2026-07-31）

## 背景

项目从单人开发进入到需要维护的阶段，需要统一的代码风格和文档约定。

## 决策

### 文档字符串：Google 风格 + 中文

- 所有 Python 文件添加 Google 风格的 docstring
- **模块文档字符串** → 中文
- **函数/类文档字符串** → 中文
- 参数标注：`Args:` → `参数：`, `Returns:` → `返回：`, `Raises:` → `抛出：`
- 内联注释 → 中文
- **原因**：团队成员为中文母语者，中文文档阅读效率更高

### 代码注释：中文化

- 所有代码注释从英文改为中文
- 保持代码标识符（变量名、函数名）为英文
- **原因**：注释是给开发者读的，中文开发团队用中文注释

### 代码格式化：Ruff

- 120 行宽（比默认 88 更宽松）
- 双引号字符串
- 忽略中文相关规则：
  - `RUF001`：全角字符（中文项目使用全角标点）
  - `RUF002`：全角字符在 docstring 中
  - `RUF003`：全角字符在注释中

### 测试命名：字符串字面量 → 枚举成员

- 使用枚举成员（如 `TaskStatus.COMPLETED`）代替字符串字面量（如 `"completed"`）
- **原因**：类型安全，IDE 自动补全更好，重构更安全

### 类型检查：Pylance 零报错

- 修复所有 Pylance 类型错误（80 → 0）
- 添加 `Optional` 守卫，避免空值传递
- 为 Pydantic 模型添加 `ConfigDict(populate_by_name=True)` 支持别名构造

## 影响

- 正向：中文文档提高了团队理解效率
- 正向：Pylance 零报错减少了运行时类型错误
- 正向：Ruff 统一配置消除了代码风格争议
- 约束：中文文档字符串对非中文开发者不友好
