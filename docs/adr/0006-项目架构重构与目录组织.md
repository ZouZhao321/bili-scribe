# ADR 0006: 项目架构重构与目录组织

## 状态

已接受（2026-07-31 → 2026-08-05）

## 背景

项目从单文件 (`fetch_transcript.py`) 发展到包含 CLI 工具、API 服务、Shell 脚本的复杂项目。需要清晰的目录结构反映架构层次。

## 决策

### 架构分层

按 **核心引擎 → 使用方式** 分层组织：

```
bilibili-transcript/
├── src/core/       # 核心引擎 — faster-whisper 封装 + B 站 API 交互
├── src/cli/        # 命令行工具 — 持久化队列 + cron 调度
├── src/web/        # FastAPI 服务 — 异步队列 + 持久化 + Webhook
└── tests/          # 测试套件
```

### 核心引擎拆分

将单体 `transcriber.py` 按职责拆分为：

| 文件 | 职责 |
| ------ | ------ |
| `bilibili.py` | B 站 API 交互（视频信息/字幕/音频流） |
| `transcriber.py` | 仅 Whisper 转录 + 时间戳格式化 |
| `runner.py` | CLI 编排入口，三级降级策略 |

### CLI 迁移：Shell → Python

- **删除** `src/shell/`（bili.sh, bili_save.sh, bili_queue.sh 等）
- **新建** `src/cli/`，将 shell 脚本重写为 Python
- **原因**：Shell 脚本在参数传递、错误处理、跨平台兼容性上不如 Python
- **消除 subprocess 调用**：将转录逻辑从 subprocess 调用改为直接调用核心函数

### 目录结构演进

| 版本 | 目录结构 | 问题 |
| ------ | ------ | ------ |
| v1 | 根目录平铺 | 混乱，无层次 |
| v2 | `src/` + `api/` | 命名不一致 |
| v3 | `src/core/` + `src/shell/` + `src/web/` | shell 不如 CLI |
| **v4（当前）** | `src/core/` + `src/cli/` + `src/web/` | 统一 Python |

## 影响

- 正向：架构清晰，职责分离
- 正向：核心引擎可被 CLI 和 API 复用，无重复代码
- 正向：消除 subprocess 调用，减少了 30% 的代码复杂度
- 约束：所有使用方式都要通过 Python 入口
