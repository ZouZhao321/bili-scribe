# ADR 0003: 持久化队列与调度策略

## 状态

已接受（2026-07-28 → 2026-08-05）

## 背景

需要批量转录大量 B 站视频（网文写作教学视频），同时服务器资源有限（3.6GB RAM，4 核 CPU）。需要一个可靠的队列系统，支持：
1. 持久化任务状态（进程重启不丢失）
2. 自动重试失败任务
3. CPU 和内存感知调度（避免资源耗尽导致系统卡死）

## 决策

### 存储后端：JSON 文件（而非 SQLite）

- **原因**：零依赖，无需安装数据库，手动查看和编辑方便
- 每个任务存储为独立 JSON 文件在 `~/.bilibili-api/tasks/` 下
- 启动时扫描目录恢复未完成的任务
- **替代方案**：SQLite（需要安装，运维复杂），Redis（需要额外服务）

### 调度策略：CPU 感知 + 内存感知

- CPU 使用率 < 50% 时自动取任务执行
- 可用内存 ≥ 模型需求 90% 时才执行，避免 OOM
- 模型内存需求表（队列调度用）：

| 模型 | 最小可用内存 |
| ------ | ------------- |
| tiny | 500 MB |
| base | 1.0 GB |
| small | 2.0 GB |
| medium | 3.5 GB |
| large-v3 | 5.5 GB |

### 调度触发：cron 轮询（每 10 分钟）

- 通过 `install-cron` 命令安装定时任务
- 每 10 分钟检查队列，有任务且资源充足时执行

### 超时保护：6 小时僵死检测

- 任务运行超过 6 小时视为僵死，自动放回队列重试
- 失败最多重试 3 次

## 影响

- 正向：重启后任务状态完整保留
- 正向：CPU 和内存感知避免了资源耗尽导致的系统卡死
- 正向：cron 调度在 Postgres/Redis 不可用时仍能正常工作
- 约束：JSON 文件不适合高并发场景（本项目单工作者，无此问题）
- 约束：cron 轮询有 10 分钟延迟，不适合实时需求
