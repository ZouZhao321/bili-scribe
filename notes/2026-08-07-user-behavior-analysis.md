# 用户行为模式分析与标准化动作

**日期**: 2026-08-07

## 问题

通过分析 2026-07-27 至 2026-08-07 的全部会话记录，提炼用户与 Pi 的交互模式，建立可复用的标准化动作。

## 用户行为模式

### 1. 链接发送（最高频）

用户发送 B 站视频链接进行转录，格式多样：

| 格式 | 示例 |
|------|------|
| 完整 URL | `https://www.bilibili.com/video/BV1xxx` |
| 短链接 | `https://b23.tv/xxx` |
| 纯 BV 号 | `BV1Gm421W75K` |

### 2. 极简指令风格

用户使用精简短句而非完整句子，Pi 需理解隐含意图：

| 用户说的 | 实际意图 |
|---------|---------|
| "分析当前项目" | 读取项目结构+关键文件，输出结构化分析 |
| "下载所有模型" | 下载 tiny/base/small/medium/large-v3 全部 Whisper 模型 |
| "y" | 确认执行（yes） |
| "继续" | 继续之前中断的操作 |

## 标准化动作

### 动作 A：收到 B 站链接 → 转录

1. 解析 URL → 提取 BV ID
2. 检查 `out/` 目录是否已有该 BV 的转录结果
3. 如有 → 展示已有文稿路径
4. 如无 → 默认加入队列，使用 base 模型 → 执行转录
5. 输出结果路径和摘要

### 动作 B：收到合集链接 → 批量下载

1. 解析合集 URL → 获取合集内所有视频 BV 号
2. 全部视频默认加入队列（不直接执行）
3. 默认使用 base 模型
4. 展示队列状态

### 动作 C：收到项目分析请求

1. 读取项目目录结构
2. 读取 README.md, pyproject.toml, AGENTS.md
3. 读取 docs/agents/ 下相关文档
4. 输出结构化分析报告

### 动作 D：收到状态查询

1. 先读 docs/agents/cli.md 确认命令
2. 执行 `bili-scribe queue status`
3. 展示结果

### 动作 E：bash 工具失败恢复

当 bash 返回 `hypa: command not found` 时：
→ 立即切换到 hypa_shell 执行同一命令
→ 不重试同一 bash 命令

## 关键决策

| 决策 | 选择 |
|------|------|
| 默认模型 | **base**（非 small） |
| 合集处理 | 全部视频加入队列，不直接执行 |
| 单个视频 | 默认加入队列 |
| 推送方式 | 必须通过 script/push.sh 中转 |
| 凭证管理 | .env 文件，gitignore 排除 |

## 用户偏好

- 所有回复使用中文
- 操作后自动验证结果
- 复杂操作使用 todo 任务列表
- 提交格式：`type(scope): 中文描述`
- 禁止在 main 分支直接提交，必须创建 feature 分支
